# ☁️ cf-tunnel-panel · 把自己的服务安全地发布到公网

> 🌐 **语言 / Language**：[English](README.md) · **简体中文（当前）**

> 一句话：一个网页面板，帮你用 **cloudflared 隧道** + **Caddy 反向代理**，把家里/服务器上的私有服务
> 发布成 `https://你的域名/某个路径`，**不用公网 IP、不用改路由器、不用开端口**。
> 支持**多条隧道同时在线**（快速 + 命名、或多账号多域名）。

- 版本：**v0.21.0**（Grafana 图嵌进首页）
- 适用：NAS、自建网站、Home Assistant、Jellyfin、Gitea、Immich、qBittorrent……任何 HTTP 服务
- 平台：Linux / arm64 / amd64 均可（本仓库在 Ubuntu 20.04 + Tegra arm64 上实测）

### v0.29.18 更新

- **体检历史会回答"什么老毛病"**：监控页的体检卡下面多一张表 —— 最近 24 小时里哪些检查项出过问题、各几次、最后一次是什么时候、什么说明。次数多的排前面。以前只有一条"最近 40 次"的细条，看不出"Grafana 老是超时"这种事。
- **顺手修掉它自己照出来的假失败**：`Grafana` 这项原来打的是公网主机名（穿过 Cloudflare），3 秒超时经常不够 → 体检时好时坏。现在优先用局域网地址探测、超时放宽到 6 秒，超时只算"注意"而不是"失败"（并说明可能只是慢）。
- **老配置快照压 gzip**：最近 10 份仍是明文（方便直接看/diff），更老的自动压成 `.json.gz`，读回、列快照、按快照回滚都照常。实测这个实例从 441KB 降到 146KB。
- **顺手修掉快照撞名**：同一毫秒里连写两份快照会用同一个文件名互相覆盖（脚本里真的会发生），现在撞名自动加序号。

### v0.29.17 更新

- **测试不再靠"睡一会儿"**：DOM 回归里十几处固定 `setTimeout` 换成「轮询到条件成立为止」（`waitFor`）和「等到真的发生了一次 5 秒轮询」（`pollTick`，靠统计 `/api/state` 调用次数）。固定等待在机器忙、面板刚重启时会"还没渲染完就断言"，这正是偶发 177/179 那类假失败的来源；顺带整套 DOM 测试快了几十秒。
- **顺手修掉一个真 UI bug**（就是被新写法照出来的）：从「按规则看流量」点进来时规则会闪一下高亮，但 5 秒轮询重绘一次列表，`data-focused` 标记就丢了 —— 高亮"闪一下就没"。现在记住被聚焦的规则，重绘时补回去；规则被删或换作用域时自动清除。

### v0.29.16 更新

- **出口的网络重连终于看得见了**：cloudflared 到 Cloudflare 边缘的 QUIC 连接断了会自己重连，进程没退出、原来的「重连 ×N」也不会涨 —— 但访客那一刻就是「网站抽了一下」。现在解析 cloudflared 输出里的重连信号（同一波重连 5 秒内只算一次），在出口卡片上显示「网络重连 ×N」徽标（最近 10 分钟 ≥3 次标黄，鼠标悬停能看到累计次数和最近一次时间），体检里也多了一项「出口链路稳定性」，抖动时会提示把协议从 `auto` 换成 `http2`（走 TCP，穿 NAT 更稳）。
- 顺手清理：`data/audit/` 里两份早期清理留下的 `.backup-audit-*.jsonl`（2.2MB）挪到 `data/backups/audit-cleanup/` —— 这种文件名不被保留期清扫匹配，会一直躺着。

### v0.29.15 更新

- **健康检查不再刷日志**：面板槽位原来无条件下发 `health_checks`，而平时另一色是停着的 —— 每 2 秒一次的探测失败在 Caddy 日志里堆到 **每天十几万行（占 99.85%）**，把日志文件填满、轮转变快，趋势图能覆盖的窗口跟着缩水。现在只有对端真的在监听时才下发健康检查，对端离线时上游列表里也不留它（否则每个请求都要先吃一次 connect refused）。
- 槽位上下线会被守护进程发现并**自动重推一次配置**，滚动升级期间依旧是双上游 + 健康检查，切换窗口没有变差。
- 体检新增第 13 项「访问日志」：报最近 10 分钟访问行/健康检查行数量与噪音占比，以及访问行能回溯多久 —— 这项以前完全不可见。

### v0.29.14 更新

- **趋势图不再被日志轮转切断**：一直只读当前 `access.log` 的尾部 2MB，一旦 Caddy 轮转（10MB 一次），窗口内的更早记录就消失了。现在把最近的轮转文件（`.gz`）一起读进来（只取窗口内的、最多 3 个、每个上限 4MB），跨轮转的小时桶也能算对。
- **只解析访问行**：日志里 99% 是健康检查对「停着的那一色」的失败重连（每天十几万条），整段切分再逐行判断很浪费。改成按 `"logger":"http.log.access` 逐段定位，只切出真正要解析的行；加上 30 秒结果缓存（小时粒度的图看不出差别），冷启动约 190ms、后续 0ms。

### v0.29.13 更新

- **修掉流量趋势显示 0**：小时桶原来是从「现在 - N 小时」往前推出来的，最后一个桶落在上一小时，于是当前这一小时的流量全被丢掉 —— 概览页会显示「合计 0 次」，但规则里明明有流量。
- 抓取目标统计补上「（N 为备份槽位）」，不再让停着的那一色看起来像故障。

### v0.29.12 更新

## Releases 与预构建镜像

每个打了 tag 的版本都会自动发布一个 [GitHub Release](https://github.com/jianghugs/cf-tunnel-panel/releases)，
并把多架构镜像（`linux/amd64` + `linux/arm64`）推到 `ghcr.io`：

```bash
docker pull ghcr.io/jianghugs/cf-tunnel-panel:0.29.4     # 指定版本
docker pull ghcr.io/jianghugs/cf-tunnel-panel:0.29       # 0.29 系列最新
docker pull ghcr.io/jianghugs/cf-tunnel-panel:latest     # 最新
```

Release 说明直接取自 `CHANGELOG.md` 里对应版本的那一段。

也可以用仓库里的脚本一条命令发版（升版本、写 CHANGELOG、提交、打 tag、push；加 `--build` 还会构建镜像并滚动升级）：

```bash
tools/release.sh 0.30.0 --notes-file /tmp/notes.md --build
tools/release.sh 0.30.0 --notes-file /tmp/notes.md --dry   # 只打印计划，不写文件
```

**怎么发一个版本**（维护者）：改 `package.json` 的版本号 → 在 `CHANGELOG.md` 加 `## vX.Y.Z` 段 →
提交 → `git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z`。剩下的 `release` workflow 会自动做
（构建双架构镜像、推 ghcr、创建 Release），不需要手工推镜像。tag 里带 `-`（如 `v0.30.0-rc.1`）
会被标成 prerelease。

## 1. 它到底做了什么

很多人第一次接触会被三个名词绕晕，先用一句话说清：

| 名词 | 大白话 |
|---|---|
| **cloudflared** | 一个跑在**你机器上**的小程序。它主动连到 Cloudflare，形成一条"隧道"。别人访问你的域名时，请求从 Cloudflare 顺着隧道送到你机器上。**因为是你往外连，所以不需要公网 IP、不需要端口映射。** |
| **Caddy** | 一个反向代理。它是**门口的接待员**：看请求的路径（`/jellyfin`）和域名，决定送给哪个内部服务（`127.0.0.1:8096`）。 |
| **面板（本项目）** | 一个网页。你在这里点几下，它就帮你**启动 cloudflared**、**生成 Caddy 配置并热加载**。不用记命令行参数。 |

数据流（从上到下读）：

```
访客浏览器
   │  https://xxx.trycloudflare.com/jellyfin
   ▼
Cloudflare 边缘（TLS 在这里终结，隐藏你真实 IP）
   │  隧道（cloudflared 主动外连，无需入站端口）
   ▼
你机器上的 cloudflared  →  http://127.0.0.1:8080  ← 本栈的 Caddy（接待员）
                                     │  按规则匹配 path / host / method / 来源 IP
                                     ▼
                            http://127.0.0.1:8096  ← 你的 Jellyfin
```

**关键设计一句话**：在 token 托管模式下，隧道的入口由 Cloudflare 云端决定，
所以本项目的做法是——**让云端把所有流量都交给本地 Caddy:8080，分流全部在 Caddy 里做**。
好处是：改分流规则 = 改 Caddy 配置（毫秒级热加载），**隧道完全不用重启，公网域名不会变**。

## 2. 三个容器分别是什么

`docker-compose.yml` 里有三个服务，**全部 `network_mode: host`**：

| 服务 | 镜像 | 作用 | 端口 |
|---|---|---|---|
| `panel` | 本仓库 Dockerfile | 网页面板 + 内嵌 cloudflared 二进制（面板负责 spawn 它） | `8090` |
| `caddy` | `caddy:2-alpine` | 代理入口，接收隧道流量并按规则分流 | `8080`（入口）、`127.0.0.1:2019`（admin，仅本机） |
| `demo` | `traefik/whoami` | 演示上游：把你发来的请求头原样打回来，用来验证链路 | `8091` |

> **为什么必须用 host 网络？**
> 隧道里的"上游"地址是 `127.0.0.1:8080`。如果容器用桥接网络，容器里的 `127.0.0.1` 是容器自己，
> 连不到 Caddy，也连不到你机器上那些只监听本机的服务（Jellyfin、Home Assistant 大多只监听本机/内网）。

## 4. 第一次用：3 步出效果

### 第 ① 步：确认隧道

面板「隧道出口」卡片里，第一条出口默认就是 **快速隧道**，直接点它卡片上的「启动」。

快速隧道不需要任何账号：十几秒后卡片头上会出现状态和 `https://xxx-xxx-xxx.trycloudflare.com` 域名，
这就是你的**临时公网入口**（卡片右上「复制公网链接」/「二维码」都能拿到它）。

> 想同时要多个入口？点卡片下方「＋ 新增隧道出口」就能再加一条，多个出口**可以同时在线**，
> 详见 [§5.3 同时跑多个隧道出口](#53-同时跑多个隧道出口多条-cloudflared-并行)。

> ⚠️ 快速隧道的域名**每次重连都会变**（容器重启、隧道重启都会变），只适合试跑。
> 想长期用 → 看下一节换成**命名隧道**。

### 第 ② 步：加一条规则

在「代理规则」卡片里：

1. 点 **+ 添加规则**，或者从「从模板快速添加…」里选一个（Jellyfin / 群晖 / Home Assistant / Immich…）
2. 填两格最关键：
   - **路径前缀**：公网访问时 URL 里的第一段，例如 `/jellyfin`
   - **上游**：服务在本机的地址，例如 `http://127.0.0.1:8096`
3. 点 **保存并下发到 Caddy**

保存成功后，Caddy 状态会变成「已同步」，**不用重启隧道**。

### 第 ③ 步：访问

把「当前公网入口」+ 路径拼起来，例如：

```
https://xxx-xxx-xxx.trycloudflare.com/jellyfin
```

打不开时先看面板下方的「实时日志」：

- 紫色 `[caddy]` 里有 `已下发 N 条代理规则` = 规则生效了
- 页面显示"这条路径没有匹配的代理规则" = **路径前缀写的不一样**（注意大小写、末尾不要带 `/`）
- 502/空白 = **上游地址不通**（在宿主机上 `curl 127.0.0.1:端口` 试试）

## 5. 两种隧道 + 多个出口

| | 快速隧道（quick） | 命名隧道（named） |
|---|---|---|
| 需要账号 | 不要 | 要 Cloudflare 账号 + 域名 |
| 域名 | 随机、会变 | 你自己的，固定 |
| 稳定性 | 适合试跑、临时分享 | 长期使用 |
| 上游地址 | 由面板的 `--url` 参数决定 | **由 Cloudflare 后台的路由决定** |

### 5.1 快速隧道

面板里选「快速隧道」→ 填「隧道指向」（默认 `http://127.0.0.1:8080`，指向 Caddy）→ 启动。
拿到 `https://xxx.trycloudflare.com` 就能用。

### 5.2 命名隧道（推荐长期用）

> 这一节是从**零**开始的完整走法：假设你只有一个域名，Cloudflare 后台一次都没点过。
> 全程约 8 分钟，只需要做一次；做完之后，面板这边只要贴一串 token。

#### 5.2.0 中英文界面对照（先认路）

Cloudflare 控制台分中英文两套叫法，下面这些是同一个东西：

| 英文 | 中文 | 在哪 |
|---|---|---|
| Zero Trust / Cloudflare One | 零信任 / Cloudflare One | <https://one.dash.cloudflare.com> |
| Networks | 网络 | 左侧菜单 |
| Tunnels | 隧道 | 网络下面 |
| Create a tunnel | 创建隧道 | 隧道页右上 |
| Public Hostname | 公共主机名 | 隧道详情页的页签 |
| Service / Type / URL | 服务 / 类型 / URL | 添加主机名的表单里 |
| Subdomain / Domain / Path | 子域 / 域 / 路径 | 同上 |

找不到入口就在顶部搜索框搜 `Tunnel`。

#### 5.2.1 先决条件（先确认，别急着点）

| 条件 | 怎么确认 | 不满足怎么办 |
|---|---|---|
| 域名已经托管在 Cloudflare | 控制台首页能看到该域名，状态 **Active** | 先「添加站点」，再去域名商把 NS 改成 Cloudflare 给的两条 |
| 能进 Zero Trust 面板 | 左侧能看到「零信任 / Zero Trust」 | 首次进入会让你起一个 team name（随便填）+ 选 **Free** 计划（50 用户内免费） |
| 面板容器在跑 | `curl -s 127.0.0.1:8090/healthz` → `{"ok":true,...}` | 回 §3 |
| Caddy 在 8080 监听 | `ss -ltnp \| grep 8080` | 面板显示「Caddy：未就绪」时看日志紫色行 |

#### 5.2.2 第一步：创建隧道，拿到 token

1. 打开 <https://one.dash.cloudflare.com> → 左侧 **网络 → 隧道**
2. 右上 **创建隧道** → 连接器类型选 **Cloudflared** → 下一步
3. 名字填一个好认的，比如 `my-panel`（只影响显示，不影响功能）→ 保存
4. 出现「安装并运行连接器」页面，上面有一长串 **token**（`eyJhIjoi...` 开头，通常 180 字符以上）
   - 点复制，先贴到记事本里 —— 面板只需要这一串
   - ⚠️ **不要**执行这一页给你的 `cloudflared.exe service install` / `systemctl start cloudflared`。
     我们已经有一个连接器了（面板拉起的那个），再装一个会**抢同一条隧道**，
     典型症状是「一会儿能开一会儿 1033、隧道页连接数乱跳」
5. 先别关这个页面，下面的「公共主机名」就在同一个隧道详情里

#### 5.2.3 第二步：加一条「公共主机名」，把域名指到本机 Caddy

隧道详情页 → **公共主机名** 页签 → **添加公共主机名**：

| 字段 | 填什么 | 为什么这么填 |
|---|---|---|
| 子域 | `app`（想直接用根域名就留空） | 最终地址 = 子域 + 域，即 `app.example.com` |
| 域 | 下拉选你的域名 | 必须是本账号里的域 |
| 路径 | **留空** | 留空 = 整个域名都进 Caddy，由面板规则再分流；填 `/*` 也一样 |
| 服务 · 类型 | **HTTP** | 本地 Caddy 是明文 `:8080`。这里选 HTTPS 必然 502 |
| 服务 · URL | `127.0.0.1:8080` | 必须是 **Caddy** 的端口：不是面板 8090，也不是业务端口 8091/8082 |
| 附加应用程序设置 | 一般不动 | 只有上游是老式自签 HTTPS 才需要 `TLS → 无 TLS 验证` |

保存后，Cloudflare 会**自动**建一条 CNAME 指向 `<隧道ID>.cfargotunnel.com`（橙色云 = 已代理）。
**不要**手工去 DNS 页面加 A 记录，也不要指向你自己服务器 IP —— 隧道模式下源站根本没有公网 IP。

链路长这样，记住这条线就知道每个字段对应哪一段：

```
   浏览器
     │  https://app.example.com
     ▼
   Cloudflare 边缘        ← TLS 在这里终结；缓存/WAF/Access 都在这一层
     │  Cloudflare 隧道     ← cloudflared 主动往外连，本机不用开任何入站端口
     ▼
   本机 cloudflared        ← 面板 spawn 的进程（host 网络）
     │  HTTP → 127.0.0.1:8080   ← 就是你在「服务 URL」里填的那一格
     ▼
   Caddy :8080             ← 按 域名/路径/方法/IP 分流
     │  HTTP → 127.0.0.1:8091 / :8088 / :8082 ...
     ▼
   你的真实服务
```

#### 5.2.4 第三步：回面板贴 token

1. 面板「隧道模式」切到 **命名隧道**（切完会显示「有未保存的改动」提示，这是正常的，见 v0.2.2 说明）
2. 把 token 粘进 **Tunnel Token**（保存后不再回显；留空 = 不修改）
3. **公网域名** 填 `app.example.com`（只用于显示和生成二维码，不会自动改 Cloudflare）
4. 点 **保存并重启隧道** → 上方徽章应变成「隧道：运行中」

#### 5.2.5 第四步：四条命令，坏在哪一层一目了然

```bash
# ① 连接器连上没有（看面板日志里的 cloudflared 行）
docker logs cf-tunnel-panel --tail 100 2>&1 | grep -iE 'Registered tunnel connection|Unauthorized|Invalid'
#   正常：Registered tunnel connection connIndex=0 ... （通常 4 条，对应 4 条边缘连接）
#   异常：Unauthorized / Invalid tunnel secret → token 错，或已在 Cloudflare 侧刷新过 token

# ② 本地 Caddy 通不通（这层坏了，公网必然 502）
curl -sI http://127.0.0.1:8080/ | head -1

# ③ DNS 指到哪
dig +short app.example.com
#   应返回 Cloudflare 的 104.x / 172.x；返回隧道 UUID 或空 → DNS 没建好

# ④ 公网整条链路
curl -sI https://app.example.com/ | head -3
```

| 第 ④ 步看到什么 | 含义 | 去哪查 |
|---|---|---|
| `200` | 全通 | 收工 |
| `401` | 规则里设了基础认证 | 正常，带 `-u 用户:密码` 再试 |
| `502` | cloudflared 连上了，但 Caddy 没应答 | 第 ② 步；或「服务 URL」端口写错 |
| 面板风格 404 文案 | 到了 Caddy 但没有匹配规则 | 面板加规则 / 检查路径前缀与「剥离前缀」 |
| 页面出现 **1033** | 隧道当前没有在线连接器 | 第 ① 步；`docker ps` 看面板容器 |
| 页面出现 **530** | Cloudflare 找不到隧道源 | 隧道是否被删、token 是否属于别的隧道 |
| 页面出现 **1016** | DNS 记录指向的源站解析失败 | 删掉手工加的 A 记录，改用自动 CNAME |

#### 5.2.6 多个服务怎么规划（一次想清楚，省得返工）

| 方案 | Cloudflare 里加几条主机名 | 面板里怎么配 | 适合 |
|---|---|---|---|
| **多子域名（推荐）** | 每个服务一条，**都**指向 `127.0.0.1:8080` | 每条规则的「域名」填子域名 | 应用互不干扰，Cookie/静态资源都不打架 |
| 单域名 + 子路径 | 只加一条（路径留空） | 每条规则填「路径」前缀，必要时勾「剥离前缀」 | 省事；但应用不认子路径时会白屏或登录死循环 |

> 💡 一个隧道 + 一个 Caddy 就能承载任意多个子域名：Cloudflare 那边只负责「把哪个域名送进来」，
> 「进来之后去哪」全在面板规则里决定。加服务 = Cloudflare 加一条主机名 + 面板加一条规则。

#### 5.2.7 可选：再套一层 Cloudflare Access（邮箱验证码登录）

适合「只想让自己和家人访问」的场景：

1. Zero Trust → **Access → 应用程序** → 添加 **自托管** 应用
2. 应用域名填 `app.example.com`（要和 5.2.3 里那条一致）
3. 加策略：Action = Allow，Include = Emails = 你的邮箱
4. 保存后访问会先出现 Cloudflare 登录页，验证通过才进 Caddy

⚠️ 两个坑：
- 会和面板/规则自带的认证**叠加**，变成两次登录（想要一次就只留一层）
- **会挡掉 Claude/DSH 这类客户端 App 与 `curl` 调用**（它们过不了浏览器验证码）；给移动端配对用的域名**不要**挂 Access

#### 5.2.8 命名隧道常见问题对照

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 隧道页一直「不健康 / Down」 | 本机连接器没在跑 | 面板点「启动」；看 ① 的日志 |
| 时好时坏，连接数乱跳 | 装了两个连接器抢同一条隧道 | 卸掉多装的那个（Windows 上 `cloudflared service uninstall`） |
| 提示 `Invalid tunnel secret` | token 被刷新过/贴错 | 隧道页 → 刷新 token → 回面板重贴 |
| DNS 明明加了还是 NXDOMAIN | 本地/运营商 DNS 负缓存 | `dig @1.1.1.1 app.example.com` 或等 5 分钟 |
| 502 但本地 8080 是通的 | 「服务 URL」写成了业务端口或用了 HTTPS | 改回 `HTTP` + `127.0.0.1:8080` |
| 中文界面找不到「Tunnels」 | 新版把它收进了 Cloudflare One | 左侧 **Cloudflare One → 网络 → 隧道**，或用顶部搜索 |

#### 5.2.9 安全：这串 token 等于什么？

- token 里包含隧道 ID + 隧道密钥，拿到它就能**冒名连上你的隧道**并改路由，等同于半个账号权限 —— 别贴到公开聊天里
- 面板把它存在 `data/state.json`（权限 0600），导出配置时默认**不含** token（只有 `?full=1` 才含）
- 怀疑泄露：隧道详情页 → **刷新 token** → 回面板重贴 → 保存重启（旧连接器立刻失效）
- 永远不要给面板的 `8090` 加公网主机名；`8080`/`8090` 之外也尽量不要在路由器上做端口映射

### 5.3 同时跑多个隧道出口（多条 cloudflared 并行）

**一句话**：面板里每个「隧道出口」就是一条独立的 `cloudflared` 进程，它们互不干涉，可以**同时在线**。

常见的三种组合：

| 组合 | 怎么配 | 适合谁 |
|---|---|---|
| 命名（主用） + 快速（备用） | 出口 A 命名隧道填 token/域名；出口 B 保持快速 | 主域名挂了还能用临时地址救急 |
| 两个命名隧道（不同账号） | 出口 A 填 A 账号 token，出口 B 填 B 账号 token | 家里一套域名、对外一套域名 |
| 两个命名隧道（同账号不同域名） | Cloudflare 建两条隧道，各自加公共主机名 | 主域名 + 备用域名同时对外 |

操作步骤：

1. 在云端**每条隧道都要建一次**（Cloudflare Zero Trust → 网络 → 隧道 → 创建隧道），各自复制 token；
2. 回到面板点 **＋ 新增隧道出口** → 模式选「命名隧道」→ 粘对应 token → 填公网域名 → **保存并重启**；
3. Cloudflare 里每条隧道的**公共主机名**都指向同一个 `http://127.0.0.1:8080`（本栈 Caddy）；
4. 规则默认配一份就行：无论流量从哪个出口进来，都会进 Caddy，再由规则按**域名/路径**分流；
   如果你想让某条规则**只对某条出口生效**，见 §5.4。

几个要点：

- **出口 ≠ 服务**：加出口只是多一条「进来的路」，对外暴露什么仍然由规则决定。
- **metrics 端口别撞车**：多个出口都开了 metrics 时端口要不同（或都留空）。
- **想让某个出口绕过 Caddy**（直连某个服务）：把该出口的「隧道指向」改成那个端口即可，
  但这样规则和基础认证/白名单就管不到它了，慎用。
- 面板顶部徽章显示 `隧道：N/M 在线`；「全部启动 / 全部停止」可一键操作所有出口。
- 删除出口只影响本面板，**不会**动 Cloudflare 上的隧道（云端那条隧道还在，只是没连接器在跑）。

### 5.4 一条出口一套规则（出口绑定规则）

布局是**顶部一排出口标签页（tab）＋ 左边设置、右边规则**：最上面一条 tab 条是「全局规则」和每条出口
（圆点是运行状态，标签里是模式与规则条数，点一下就切换）；切到哪条出口，右栏就只显示属于它的规则 ——
这就是「一条出口一套规则」的入口。出口本身的参数在左栏「⚙️ 出口设置」里折叠着，需要时再展开。

两种作用范围：

| 作用范围 | 怎么建 | Caddy 里生成的匹配条件 | 适合 |
|---|---|---|---|
| **全局规则** | 左栏点「全局规则」再添加 | 只按你填的域名/路径/方法/IP 匹配 | 大多数情况：不管从哪个出口来都一样处理 |
| **出口专属规则** | 左栏点某条出口，再在右边加规则 | 自动加上该出口的**公网域名**作为 Host 条件 | 想让 A 域名只能看服务甲、B 域名只能看服务乙 |

机制（了解即可）：

- 面板会读取这条出口当前的公网域名（命名隧道取你填的「公网域名」，快速隧道取运行时拿到的 `xxx.trycloudflare.com`），
  把规则的下发条件收窄成 `Host == 那个域名`，于是**别的出口的请求天然匹配不上** → 落到 404。实测：
  主出口 `/own1` → 200、第二条出口 `/own1` → 404；第二条出口 `/own2` → 200、主出口 `/own2` → 404。
- 你在规则的「域名」字段里手填了值，就以你填的为准（支持逗号分隔多个域名）。
- **快速隧道的域名每次重连都会变**，所以出口上线/掉线时面板会自动重新下发一次 Caddy 配置，不用手点。
- 出口没在跑（拿不到域名）时，绑定它的规则会**暂时不下发**，规则区顶部会出现黄条「有规则没生效：出口「X」还没有公网域名（先启动它）」。
- 想让某条规则改回「对所有出口生效」，把它删掉，在「全局规则」视角下重建即可。

## 6. 规则字段逐个讲

规则按**从上到下**顺序匹配，**第一条命中即停止**（所以特殊规则放上面，兜底放下面）。

### 6.1 常用（卡片正面就有）

| 字段 | 说明 | 例子 |
|---|---|---|
| **名称** | 只给自己看，也会写进响应头 `X-Panel-Route`（方便排障） | `家里的 Jellyfin` |
| **域名** | 匹配 Host 头，留空 = 任意域名；可以逗号分隔多个 | `app.example.com, media.example.com` |
| **路径前缀** | 自动补 `*`：写 `/demo` 实际匹配 `/demo*`（含 `/demo`、`/demo/xx`） | `/jellyfin` |
| **上游** | 内网服务地址。可省略 `http://` | `127.0.0.1:8096`、`http://192.168.1.10:5000`、`https://nas.local:5001` |
| **启用** | 取消勾选 = 暂时停用（规则保留但不下发） | |

### 6.2 高级（点每条规则右侧「高级」展开）

| 字段 | 用途 | 注意 |
|---|---|---|
| **请求方法** | 只允许某些方法，如 `GET,HEAD` | 逗号分隔；不匹配 = 404 |
| **来源 IP 白名单** | CIDR 列表，如 `192.168.1.0/24, 10.0.0.5` | 不在名单 → 404（不给探测者任何提示） |
| **剥离路径前缀** | 转发时把 `/jellyfin` 去掉 | **大部分应用不认子路径，必须勾** |
| **备用上游** | 主上游挂了自动切过去 | 触发实际是"连接失败"或超时 |
| **多上游策略** | `round_robin` / `first` / `least_conn` / `random` / `ip_hash` / `uri_hash` | 只在有两个上游（主+备）时生效 |
| **故障尝试时长** | 多久内一直尝试切换，默认 10 秒 | 设太大会让页面卡很久 |
| **超时秒数** | 上游多久不响应就断开 | 0 = Caddy 默认（无限制）；流媒体别设太小 |
| **追加请求头** | 每行 `名称: 值`，转发时加上 | 常用于补 `X-Api-Key`、`Host` |
| **改写响应头** | 每行 `名称: 值` | 如加 `X-Robots-Tag: noindex` 防被搜索引擎收录 |
| **基础认证** | 用户名 + 密码，浏览器弹框登录 | 密码只存 **bcrypt 哈希**；留空密码 = 不启用/不修改 |
| **备注** | 写给未来的自己，显示在卡片上 | |

> 🔐 基础认证适合"给朋友临时看"这种场景。需要按身份/邮箱限制、或要 SSO，
> 请用 Cloudflare Access（缺点：会覆盖整条域名，不能按路径分）。

### 6.3 模板一览（下拉里选，自动填好路径/端口/备注）

| 分组 | 模板 | 默认路径 | 默认上游 | 备注 |
|---|---|---|---|---|
| 通用网页 | whoami 演示 | `/demo` | `:8091` | 自带，用来验证链路 |

### 6.4 规则自检三件套：测上游 / 模拟匹配 / 访问统计

配规则最容易犯的错只有三类，这三样东西各治一类，**都不用去公网试**：

| 你遇到的现象 | 用哪个 | 怎么用 |
|---|---|---|
| 公网访问 502 / 一直转圈 | **测上游** | 规则卡片上点「测上游」，面板会从自己所在的机器探一次这个端口：<br>`✅ 上游可达：TCP 5ms，HTTP 200` = 服务活着<br>`❌ 端口 8096 没人监听（connection refused）` = 端口写错或服务没起 |
| 明明配了规则却命中别的规则 / 直接 404 | **模拟匹配** | 规则区下方「🔍 模拟匹配」，输入 `/jellyfin/home` 点「模拟」，立刻告诉你<br>`✅ 命中第 3 / 5 条：Jellyfin → http://127.0.0.1:8096`<br>它只做推算，不发真实请求，改顺序时反复点很安全 |
| 不知道有没有人来、404 是谁返回的 | **访问统计** | 页面下方「访问统计」点「刷新」，看最近 100 条请求的<br>时间 / 方法 / 路径 / 状态码 / 耗时 / 来源 IP，顶部还有 `2xx 3xx 4xx 5xx` 汇总 |

三个细节：

- **测上游探的是「面板所在机器」的视角**，也就是 Caddy 的视角 —— 这正是真正转发时的视角，比在自己电脑上 ping 更准。
- **模拟匹配按「从上到下、第一条命中即停」推**，和 Caddy 的实际行为一致；如果它说命中的是 `/` 那条兜底规则，说明你的具体规则排在它后面了（会有黄色提示帮你移到最后）。
- **访问统计来自 Caddy 的 access log**（`data/caddy-logs/access.log`，JSON 行，按 10MB 滚动保留 3 份）。刚启用时是空的，有流量才有；重建 Caddy 容器后日志会续写同一个文件。

另外两个省事的功能：每条规则上的 **↑ / ↓** 用来调顺序（只在同一作用域内移动，不会打乱别的出口的规则），**导出 / 导入单条** 可以把一条规则复制成 JSON 带到另一台机器。

### 6.5 工具箱（Docker / 分享 / 测试器）

面板下半部分的「工具箱」一块，三个小工具都是为"少敲命令"准备的。

**① 🐳 Docker 容器 → 一键加规则**

面板会读本机 Docker（compose 里已把 `/var/run/docker.sock` 只读挂进来），列出所有容器：状态、镜像、端口、推断出的上游地址。点容器右边的「加规则」，就会在规则列表底部追加一条：

```
名字：jellyfin        路径：/jellyfin        上游：http://127.0.0.1:8096
```

端口是怎么猜的：

| 容器网络 | 用的地址 |
|---|---|
| 有发布端口（`8082→8080`） | `http://127.0.0.1:8082` |
| `network_mode: host`（本栈就是） | 读镜像的 `EXPOSE` 端口，优先挑 80/443/3000/5000/8000/8080 这类"像 Web 的"，跳过 22/3306/6379/2019 这类"肯定不是 Web 的" |
| 只有内网端口 | `http://<容器IP>:<端口>` |

猜错了直接在规则卡里改上游就行。加完记得点「保存并下发」，它只是**帮你填好表单**，不会偷偷下发。

**② 🔗 一次性分享链接**

给同事临时看一眼某个服务，又不想给密码、也不想动主规则：

- 填上游（如 `http://127.0.0.1:8091`）、说明、有效分钟（默认 30，最多 7 天）→ 「生成链接」
- 得到 `https://xxx.trycloudflare.com/s/-SD3Gb8S6Pzz`，**复制发出去就行**
- 到期后面板自动把它从 Caddy 里摘掉（每 15 秒清一次），规则列表里不会留垃圾

实现上它是独立的 `state.shares`，走 `/s/<token>` 前缀 + `strip_path_prefix` + `reverse_proxy`，**不占用规则位、不参与优先级**。分享链接没有额外鉴权 —— 拿到 URL 的人都能看，这正是"分享"的意思；要收回就点「删」。

**③ 🧪 面板内测试器**

输入路径（可带 `?` 参数）和可选的 `Host` 头，面板就在本机打一次自己的 Caddy，把状态码、耗时、字节数、响应头、前 600 字节正文都打出来：

```
200  122ms  873 字节
http://127.0.0.1:8080/demo
content-type: text/plain; charset=utf-8
via: 1.1 Caddy

Hostname: user
IP: 127.0.0.1
```

用途：**分清"是隧道断了还是规则配错了"**。测试器能通、公网不通 → 问题在隧道；测试器也不通 → 规则/上游写错了。填了 `Host` 还能验证"按域名分流"的规则有没有生效。

#### 一次性分享链接打不开？（v0.7.8 已修）

症状：生成链接后打开是 `401`（要求面板登录）或 `404`（面板说找不到页面）。

原因：Caddy 的规则是**从上往下第一条命中即停**。分享路由以前排在业务规则后面，而只要有一条 `路径 = /` 的兜底规则（比如「面板自己」或「静态站首页」），`/s/<token>` 就先被它吃掉——于是请求跑到面板上，自然要登录、然后 404。

现在分享路由固定插在「安全层之后、业务规则之前」，并且同时匹配 `/s/<token>` 和 `/s/<token>/*`（子路径、CSS、图片都能透传）。已经存在的分享链接不用重建，重启面板后自动生效。

### 6.6 维护模式与 IP 黑名单

**维护模式**：设置卡里勾上「开启后整站返回 503」。开启后 Caddy 的**所有请求**都返回一张维护页（带 `Retry-After: 300`，搜索引擎会当临时状态处理），隧道和 cloudflared **不用停**，外部看到的是"暂时不可用"而不是"连接失败"。改完点保存即刻生效，取消勾选即恢复。

**IP 黑名单**：`1.2.3.4, 10.0.0.0/8` 这样填，命中的请求在最前面就被 `403` 掉 —— 比在每条规则里写白名单更彻底（连"这个路径存不存在"都探不出来）。

> 白名单（规则级 `来源 IP 白名单`）和黑名单（全局）可以一起用：黑名单先拦恶意段，白名单再收窄单条规则。

**限流**：面板里有开关和参数，但标准 `caddy:2-alpine` **不带** `rate_limit` 模块，所以默认不会下发（只会在日志里提示一次）。要真用得上，按 [docs/RATELIMIT.md](docs/RATELIMIT.md) 换一个用 `xcaddy` 编的自定义镜像，再把 `CADDY_RATELIMIT=1` 打开。

### 6.7 掉线通知

隧道半夜掉线、域名悄悄变了，人都不会在场。填一个 Webhook，面板会在三种情况下推一条：

| 事件 | 什么时候发 |
|---|---|
| 出口掉线 | 出口从 running 变成 error/stopped（附 `lastError`、模式、主机名） |
| 换域名 | 快速隧道重连后拿到新域名（附新旧地址对比） |
| 下发失败 | Caddy 拒绝配置（附错误原文，通常是新版 Caddy 字段变动） |

格式支持：**通用 JSON**（`{title,text,event,ts,host}`，自己接 n8n/自建服务）、**钉钉机器人**、**飞书机器人**、**Bark（iOS）**。填完点「发送测试通知」当场验证，收不到就去看「实时日志」—— 每次发送（成功/失败）都会记一行。

### 6.8 Cloudflare API 集成（可选，v0.7.9 增强）

这一节讲清楚三件事：**能做到什么、Token 到底要给哪些权限、点每个按钮时背后发生了什么**。

#### 6.8.1 它替你做哪几件事

| 你能在面板里做的事 | 以前要跑到 Cloudflare 后台点 |
| --- | --- |
| 验证 Token 是否有效，并自动列出你名下的**账号**和**域名** | 靠记忆找 Account ID / Zone ID，还容易复制错位 |
| 列出云端所有隧道：名字、状态（healthy/down）、在线连接数、ID | Tunnels 列表页翻 |
| 一键**新建隧道**，并顺手在本机加一条出口（token 自动填好） | 建隧道 → 复制 token → 回面板粘 → 加出口，四步 |
| 复制任意一条隧道的 token | 进隧道详情 → 配置 → 复制那一长串 |
| 建 / 查 / 删 **DNS 记录**（重点：`CNAME → <隧道ID>.cfargotunnel.com`） | DNS 记录页手填，proxied 常忘勾 |
| 删除云端隧道 | Tunnels → 删除，还要确认没有 connector 在跑 |

**它做不到的一件事（很重要）**：**公共主机名（Public Hostname）只能去后台加**。Cloudflare 的 API 对「云端托管型（`config_src=cloudflare`）」隧道不开放 ingress 编辑，所以「`panel.example.com` → `http://127.0.0.1:8080`」这个映射必须你在后台 → 你的隧道 → 路由 → 添加路由 里填。面板能帮你把 DNS 那条 CNAME 建好，但**只建 CNAME 不加主机名，打开会是 Cloudflare 1033 错误**（下面 6.8.7 有对照表）。

#### 6.8.2 五步接上（照着点）

**第 1 步：建一个 Token**

Cloudflare 后台 → 右上头像 → **My Profile** → 左侧 **API Tokens** → **Create Token** → 最下面 **Create Custom Token**。

**第 2 步：按这张表勾权限（最小集）**

| 权限 | 用途 | 不给会怎样 |
| --- | --- | --- |
| `Account` · `Cloudflare Tunnel` · **Edit** | 建/删/列隧道、取 token | 隧道相关全部报权限不足 |
| `Zone` · `DNS` · **Edit** | 建/查/删 DNS 记录 | DNS 区域报权限不足 |
| `Account` · `Account Settings` · **Read** | 「验证」时列出账号（可选） | 验证仍能过，只是列不出账号，要手填 Account ID |
| `Zone` · `Zone` · **Read** | 「验证」时列出域名（可选） | 列不出域名，要手填 Zone ID |

资源范围：`Account resources` 选你的账号；`Zone resources` 可以选「所有域名」或只选你要挂的那个域名（更安全）。

**第 3 步：复制 Token**（`Create Token` 后只显示一次，保存好）

**第 4 步：回面板填**

工具箱 → 「Cloudflare API（可选）」卡片：

1. `API Token` 粘贴刚才那一串
2. 点右上角 **「验证 Token / 拉账号与域名」**
3. 看到「有效（…）」就说明通了；面板会顺手把 **Account ID / Zone ID 自动填好**（多个域名时会列出表格，点「用这个」选一个）
4. 点 **「保存 API 配置」**（这一步才真正写盘，不点等于没填）

**第 5 步（可选）：把已有的隧道接进面板**

点「刷新云端隧道」 → 在表格里找到那条隧道 → 点 **「复制 token」** → 去「隧道出口」页 → 新建出口 → 模式选「命名隧道」→ token 粘进去 → 公网域名填和后台公共主机名**完全一致**的那个 → 保存并启动。

#### 6.8.3 点每个按钮背后发生了什么

| 面板动作 | 调用的接口 | 说明 |
| --- | --- | --- |
| 验证 Token / 拉账号与域名 | `GET /user/tokens/verify`、`GET /accounts`、`GET /zones` | 三个都试一遍；只要有一个成功就算 token 可用。受限 token 可能调不通 `verify`，但账号/域名能读，面板会显示「有效（…够用）」 |
| 刷新云端隧道 | `GET /accounts/<acc>/cfd_tunnel?is_deleted=false` | 返回名字/状态/连接数/ID，连接数 = 当前有几个 connector 在跑（0 表示没启动） |
| 复制 token | `POST /accounts/<acc>/cfd_tunnel/<id>/token` | 直接写进剪贴板，省得去后台翻 |
| 新建隧道 | `POST /accounts/<acc>/cfd_tunnel`（`config_src=cloudflare`） | 名字只能字母数字和 `. _ -`，最长 60；建完立即取 token |
| 建 CNAME | `POST /zones/<zone>/dns_records` | `type=CNAME`、`content=<隧道ID>.cfargotunnel.com`、`proxied=true`，comment 打上 `created by cf-tunnel-panel` 便于事后认领 |
| 查 DNS | `GET /zones/<zone>/dns_records?name=<名字>` | 留空则列前 100 条 |
| 删 DNS | `DELETE /zones/<zone>/dns_records/<id>` | 不可恢复 |
| 删隧道 | `DELETE /accounts/<acc>/cfd_tunnel/<id>` | 只删云端；本机出口还在，但会因为 token 失效而报「Token 无效」并停止重试 |

所有请求都从**面板所在的这台机器**直接打到 `api.cloudflare.com`（不走隧道），超时 15 秒；失败会把 Cloudflare 返回的 `errors[].message` 原样显示出来，不会吞掉。

#### 6.8.4 DNS 记录管理怎么用

典型用途不是「给隧道建 CNAME」（那个 6.8.2 第 4 步的「新建隧道 + CNAME」已经做了），而是：

- 你的域名原本 A 记录指向 VPS（比如 `api1.example.com → 1.2.3.4`），想改成走隧道 → 先删旧 A，再建 CNAME 指向 `cfargotunnel.com`
- 建子域名给某个服务用，`proxied` 一定要开（关掉就是纯 DNS，Cloudflare 的安全/WAF/真实 IP 全没了）
- 忘了某个域名指到哪 → 在「按域名查记录」里填上名字，一眼看到

小抄：

| 想做的事 | 记录类型 | 内容 |
| --- | --- | --- |
| 域名走隧道 | `CNAME` | `<隧道ID>.cfargotunnel.com` |
| 域名指向 VPS（不经 CF 代理） | `A` | VPS 的 IPv4，`proxied` 关 |
| 域名指向 VPS（经 CF 代理，能加 WAF） | `A` | VPS 的 IPv4，`proxied` 开 |

#### 6.8.5 错误对照表

| 面板报的错 / 浏览器现象 | 真实原因 | 怎么办 |
| --- | --- | --- |
| `Cloudflare API 失败：Invalid API Token` | token 复制不完整，或已被删/过期 | 重新建一个，粘贴时注意别带上空格 |
| `…Authentication error` / `…not authorized` | 权限没给够（少 `Cloudflare Tunnel:Edit` 或 `DNS:Edit`） | 回 token 编辑页补权限 |
| `还没填 Account ID` | 只存了 token，没存账号 | 点「验证」自动带出，然后**记得点保存** |
| 打开域名 → **Cloudflare 1033** | CNAME 有了，但隧道里**没有配这个公共主机名** | 后台 → 隧道 → 路由 → 添加路由（这也是 API 做不了的那一步） |
| 打开域名 → **530 / 1016** | 主机名配了，但 origin 地址填错/服务没起 | 检查是不是 `127.0.0.1:8080`（Caddy），以及 Caddy 在跑 |
| 面板显示连接数 0 | 本机没有 cloudflared 在跑这条隧道 | 面板「隧道出口」里点启动；或 token 填错了 |
| `Zone ID` 报错但账号能读 | token 少了 `Zone:Read`，或 Zone ID 选成了别的域名 | 手动从后台复制：域名概览页右下角 API → Zone ID |

#### 6.8.6 安全须知

- token 只存在服务器本地 `data/state.json`（权限 0600），**不会**出现在 `/api/state` 响应里（只回 `hasToken: true`），导出的脱敏配置也不带它。
- 面板一旦挂到公网，**务必先开面板登录**（设置页填用户名密码）；不然拿到面板就等于拿到你的 Cloudflare token。
- 权限按最小集给：只挂一个域名就只授权那一个 Zone，别选「所有域名」。
- 轮换：怀疑泄露 → 后台 Roll/Delete 该 token → 面板里粘新的 → 点保存。旧 token 立即失效，本地隧道不需要重建。
- 给 Token 加 **TTL / IP 限制**（Create Token 页高级选项）能再压一层风险。

### 6.9 面板会替你盯着的三件事（v0.7.1）

不用自己 `docker exec` 进去猜，页面上直接能看到：

| 现象 | 面板怎么提示 | 在哪看 |
| --- | --- | --- |
| 上游端口没起（502） | 每条规则上游现况小圆点（绿=通、红=不通、灰=还没探），鼠标悬停看毫秒数 / 错误码；总览页顶部黄条列出所有不通的上游 | 代理规则页 · 总览页 |
| 前面的规则把后面的挡住 | 红条「N 条规则被前面的规则挡住、永远不会生效」，并指出被哪条拦的；最常见是 `/` 兜底规则排在中间 | 代理规则页 · 总览页 |
| 快速隧道被 Cloudflare 限流 | 出口卡片显示「限流中，N 秒后自动重试」，重试间隔按 30s → 60s → 120s … 最多 15 分钟指数退避，不会每 5 秒撞一次 | 隧道出口页 |

再加一个排查利器：**工具箱 → 生成的 Caddy 配置**，点一下就把面板当前翻译出来的 Caddy JSON 原样贴出来（`GET /api/caddy/config`）。规则「明明配了却没生效」时，先看这里——如果某条规则根本不在 `routes` 里，要么被 `enabled` 关了，要么它的出口当前没有公网域名（会被跳过并出现在 `skipped` 列表里）。

> 上游健康由服务端每 60 秒做一次 TCP 探测（只 connect，不发业务请求，开销可忽略），所以圆点最多滞后一分钟。

### 6.10 通知的冷却与静默时段（v0.7.2）

出口掉线常常是「掉一下、自己起来、又掉一下」，不设限的通知能一晚上刷你几十条。设置页 · 通知里两个新字段：

| 字段 | 作用 | 建议值 |
| --- | --- | --- |
| 相同事件冷却（秒） | 同一个事件（掉线 / 换域名 / Caddy 失败）在 N 秒内只提醒一次，其余写进面板日志 | `300`（5 分钟） |
| 静默时段 | 这段时间内一律不发通知；支持跨零点，多段用逗号分隔 | `23:00-07:00` 或 `12:00-13:30,23:00-07:00` |

- 判断用服务器本地时区（容器默认跟宿主机一致）。
- 「发测试通知」按钮**不受**冷却和静默限制——刚配好就想验证能不能收到，点它就行。
- 被拦下的通知不会静默丢弃，面板日志里有一行 `通知冷却中（tunnelDown，距上次 42s < 300s）`，排查“为什么没收到”看这里。
- 格式写错（比如 `25:99`）保存时直接报错，不会悄悄存坏值。

### 6.11 WebSocket 自测（v0.7.2）

网页终端（ttyd / wetty）、Jupyter、Grafana 实时面板、code-server 都靠 WebSocket。这类服务“页面能打开但一片空白/一直转圈”，八成是 WS 没升级成功。

工具箱 → 链路自测里新增 **测试 WebSocket 升级**：面板会经本机 Caddy 发出一次真实的 WS 握手（`Connection: Upgrade` + `Sec-WebSocket-Key`），结果直接告诉你：

- `可以升级（101，26ms）` —— 这条规则能承载 WS 服务。
- `不能升级（HTTP 200，多半是上游不是 WS 服务或规则路径不对）` —— 常见原因：服务本身没开 WS、路径写错（ttyd 通常是 `/ws`、Jupyter 是 `/api/kernels/.../channels`）、或者用了只支持 HTTP 的老代理。

> 用 `curl` 手测 WS 必须加 `--http1.1`：HTTP/2 的扩展 CONNECT 不被接受，会给你一个假的 404；浏览器走的是 HTTP/1.1，所以浏览器里是好的。

### 6.12 备份对比（v0.7.2）

设置页 → 备份与回滚，每份备份多了一个 **对比当前** 按钮：直接列出这份备份和现在的配置差在哪——


### 6.16 只读账号（v0.8.0）

设置页 →「只读账号」填用户名 + 密码（≥6 位），保存后：

- 用这组账号登录：**所有页面都能看**，但任何写操作（改规则、改设置、建出口、删备份）会返回 `403`，
  页面顶部会弹一条黄色提示「当前是只读账号」。
- 想让别人只看状态、不让他改坏配置时用它，比共享管理员账号安全。
- 留空用户名 = 关闭只读账号。

自己验证一下：

```bash
curl -u ro:你的只读密码 http://127.0.0.1:8090/api/state        # 200
curl -u ro:你的只读密码 -X POST -d '{}' http://127.0.0.1:8090/api/settings   # 403
```

## 7. 常见玩法（照着抄）

### 7.1 把 DeepSeek Harness 本身挂出去

```
名称: DeepSeek Harness    路径: /dsh    上游: http://127.0.0.1:3080    剥离前缀: ✅
```
然后访问 `https://你的域名/dsh`。它自己的登录/配对鉴权仍然生效，多一层保护。

### 7.2 Jellyfin 媒体库

```
名称: Jellyfin   路径: /jellyfin   上游: http://127.0.0.1:8096   剥离前缀: ✅   超时: 300
```
播放视频走的是同一条隧道，注意隧道带宽。卡的话在 Caddy 侧加缓存意义不大，主要是上行带宽。

### 7.3 群晖 DSM

```
名称: 群晖   路径: /dsm   上游: http://127.0.0.1:5000   剥离前缀: ✅
```
DSM 对子路径支持一般，若登录后跳转回根路径，改用**独立子域名**（域名列填 `nas.example.com`，路径留空）。

### 7.4 同一服务开两个入口（一个公开、一个要密码）

| 名称 | 路径 | 上游 | 基础认证 |
|---|---|---|---|
| 相册-公开 | `/albums` | `127.0.0.1:2283` | 无 |
| 相册-私人 | `/private` | `127.0.0.1:2283` | `me` / `******` |

### 7.5 只允许家里网段 + 密码

路径 `/admin`，来源 IP `192.168.1.0/24`，再加基础认证 —— 双保险。

### 7.6 普通网页 / 静态站（已实测）

```
名称: 我的网站     路径: /site     上游: http://127.0.0.1:8088     剥离前缀: ✅
```
访问 `https://xxx.trycloudflare.com/site/` → 页面 + 子路径资源（`/site/pixel.svg`）都是 200。

### 7.7 数据库 Web 面板（已实测：Adminer + MariaDB 11.8 真登录）

```
名称: 数据库     路径: /db     上游: http://127.0.0.1:8082
基础认证: me / ********     （必填！）
```

实测链路：公网 `GET /db/` → 无凭证 401 → 带凭证 200（Adminer 登录页）→
提交登录表单（含 CSRF token）→ 302/303 → 跟随 → **`Database: demo - db - Adminer`，库表正常列出**。
也就是"浏览器 → Cloudflare → 隧道 → Caddy → Adminer → MariaDB"整条链路通。

> ⚠️ 数据库面板是"一个页面看/改所有数据"，务必「基础认证 + 来源 IP 白名单」双保险。
> 更保险的做法：只在 Tailscale/WARP 内网访问，公网不暴露。

### 7.8 SSH / 网页终端（已实测 WebSocket 透传）

**先说结论：真正的 SSH（22 端口）不能直接走本面板**，因为本面板是 HTTP 反向代理
（见 §7.9）。想做"网页里开个终端"，用 Web 化的终端：

```
名称: 网页终端     路径: /term     上游: http://127.0.0.1:7682     剥离前缀: ✅
```
ttyd 启动示例：`ttyd -p 7681 -c 用户名:密码 bash`（`-c` 一定要设，否则等于裸奔）。

实测：
- `GET /term/` 无凭证 → 401（ttyd 自己的 Basic Auth）
- 带凭证 → 200，页面是 `ttyd - Terminal`
- **WebSocket 升级** `GET /term/ws` → `101 Switching Protocols`（本地和**公网各测一遍都通过**）

> 💡 用 `curl` 测 WebSocket 时要加 `--http1.1`：浏览器走 HTTP/1.1 升级，而 `curl` 默认先用
> HTTP/2，走 h2 的 extended CONNECT 会被 Cloudflare/上游拒掉，看起来像 404，其实不是面板的问题。

同理可用的还有：`code-server`（网页版 VS Code，`:8080`）、`Wetty`（`:3000`）、`Shellinabox`（`:4200`）、
`Guacamole`（网页 VNC/RDP）。它们本质都是"HTTP + WebSocket"，所以本面板天然支持。

### 7.9 为什么 SSH / MySQL 原生端口不能直接挂（反例实测）

本面板（以及任何 HTTP 反向代理）只搬 HTTP 流量。**把 MySQL 端口当上游，结果是 502**：

```
名称: MySQL 原生端口   路径: /rawdb   上游: http://127.0.0.1:3307
→ 公网 /rawdb/ 返回 502，本地 /rawdb/ 也是 502
```
原因：Caddy 发的是 HTTP 请求，而 MySQL 一上来就发二进制握手包（`5a 00 00 00 0a 31 31 2e 38`…），
双方协议对不上，连接直接断。SSH 同理（`SSH-2.0-OpenSSH_...` 也是自己的协议）。

**真要用原生 SSH/MySQL，有三条正路：**

| 方案 | 做法 | 适合谁 |
|---|---|---|
| ① 网页化（推荐，本面板直接支持） | 用 ttyd / Wetty / code-server / Adminer 这类"HTTP 外壳" | 想给手机/别人一个链接就能用 |
| ② Cloudflare 隧道直连 TCP | 在 Cloudflare 后台该隧道里**再加一条公共主机名** → Service 选 `SSH` → `localhost:22`；客户端用 `cloudflared access ssh --hostname ssh.你的域名` 连接 | 想用原生 `ssh` 客户端，且能接受客户端装 cloudflared |
| ③ Tailscale / WARP 组网 | 直接用内网 IP 连，公网完全不暴露 | 只给自己设备用、追求最安全 |

> 本面板只管 HTTP 分流，**不会**去改 Cloudflare 上的 TCP 路由；方案 ② 与面板可以共存
> （面板走 `http://localhost:8080`，SSH 走 `ssh://localhost:22`，互不干扰）。

### 9.0 登录与会话
两种进法并存：

| 方式 | 给谁用 | 怎么用 |
| --- | --- | --- |
| **会话 cookie** | 浏览器 | 打开 `/login` 登录一次 → `cfp_sid` cookie，7 天有效、12 小时不动就失效 |
| **HTTP Basic** | `curl`、脚本、Prometheus | `curl -u 用户名:口令 http://host:8090/...` |

为什么要会话：Basic 每个请求都重发口令、浏览器的凭据永不过期，而且**没法撤销**——
只用 Basic 时，想踢掉某个人只能改密码，结果是把自己也踢了。有会话之后，「设置 → 登录会话」
会列出每台设备：账号、角色、来源 IP、设备、登录时间、最后活动，每行一个**踢掉**按钮，
另有「踢掉其它设备」。

几个细节：

- 会话只存在内存里：重启面板所有人需要重新登录（磁盘上不留任何会话痕迹）。
- cookie 是 `HttpOnly; SameSite=Lax`，走 HTTPS 时自动加 `Secure`。
- 用会话 cookie 发起的写请求都要过同源校验（`Sec-Fetch-Site` / `Origin`），跨站写直接 403 并记审计。
- 登录失败和 Basic 共用同一个防爆破计数器（8 次 / 10 分钟 → 锁 10 分钟）。
- 只读账号也能开会话，但写操作一律 403。

## 9. 排障速查表

| 现象 | 最可能的原因 | 怎么查 |
|---|---|---|
| 公网 404，文案是"这条路径没有匹配的代理规则" | 路径前缀不匹配 | 面板规则里的路径 vs 你访问的 URL |
| **加了规则，等一会儿又没了** | v0.4.0 及更早的 5 秒自动刷新会拿服务端旧数据覆盖「还没保存」的规则 | v0.4.1 已修：规则区一有未保存改动就暂停回填，按钮旁出现黄色提示；改完点「保存并下发到 Caddy」即可 |
| **规则明明写了，访问却 404** | 路径为 `/` 的规则是万能前缀，它要是排在前面，后面的规则永远匹配不到 | 把 `/` 那条移到最后；v0.4.1 检测到这种顺序会出黄条并给「把这条移到最后」按钮 |
| **点别的出口，规则就"不见"了** | 规则按作用域显示：点「全局规则」只看到全局的，点某条出口只看到属于它的 | 规则卡「高级」里有「作用出口」下拉，可把一条规则改到别的出口；卡片右上角标签写明「全局 / 专属」 |

### 两个踩过的坑（已在代码里修，供你避雷）

1. **Caddy 的 JSON 是原生格式**，`caddy run --config x.json --adapter json` 会报
   `unrecognized config adapter: json` —— 因为 `json` 不是"适配器"，它就是 Caddy 的原生格式。**不要加 `--adapter`**。
2. **Caddy admin 接口默认拒绝带 `Origin` 的跨源请求**。Node 的 `fetch`（undici）**默认不发 `Origin`**，
   结果是 Caddy 返回 `403 {"error":"client is not allowed to access from anywhere to origin ''"}`。
   解法：下发时显式带 `Origin: http://127.0.0.1:2019`，并在 admin 配置里写
   `origins: ["http://127.0.0.1:2019", "http://localhost:2019"]`。
3. （v0.2 新踩）**Caddy v2.11 的负载均衡字段改名了**：老写法 `load_balancing.selection.policy`
   会报 `json: unknown field "selection"`，现在要用 `load_balancing.selection_policy.policy`。

### 速度实测：代理到底有多快？（本机实测数据）

很多人担心「加了 Caddy 一层会不会变慢」，以及「隧道到底能不能看视频」。下面都是在
**Ubuntu 20.04 aarch64 / 家宽 / Cloudflare 免费套餐**上跑出来的真实数字（2026-11-15）。

> 测试方法：同一台机器上既跑客户端又跑服务端，所以公网那部分流量**两次**经过家宽
> （上行到边缘 + 下行回本机），比真实"手机在外面访问"更苛刻一些。

**① 延迟**（各 20 次，单位 ms）

| 链路 | TTFB 中位 | 整次请求 p50 | p95 |
|---|---|---|---|
| 直连应用（跳过代理） | 6.6 | 6.8 | 8.0 |
| **经 Caddy（本面板这一层）** | 7.4 | **7.6** | 10.3 |
| 经隧道 + Cloudflare 边缘 | 1055 | 1073 | 1624 |

→ **Caddy 只加 0.8 ms（约 11%）**，可以认为零成本。公网那 1 秒拆开是：
DNS 116 ms + TCP 295 ms + TLS 525 ms + 边缘↔本机再一个来回 ≈ 530 ms。

**② 吞吐**（单流下载 5 MB）

| 链路 | 速度 |
|---|---|
| 直连 nginx | **436 MB/s** |
| 经 Caddy | **302 MB/s** |
| 经隧道（公网） | **0.45 MB/s ≈ 3.6 Mbps** |
| 对照：直连 Cloudflare 边缘（不经隧道） | 1.66 MB/s 下行 / 2.38 MB/s 上行 |

**③ 瓶颈到底在哪**（三个反证）

- 换协议没用：`--protocol http2` 实测 0.43 MB/s，QUIC 是 0.45 MB/s。
- 加并发没用：6 路并发各 1 MB，聚合仍只有 0.38 MB/s → 不是"单连接限速"，是**链路总带宽**受限。
- 换入口机房没用（对吞吐）：强制走 SIN / LAX / AMS 三个不同边缘，吞吐都是 0.45 MB/s → 瓶颈在
  **cloudflared 回源那一段（家宽上行到 Cloudflare）**，不在客户端入口。

**④ 入口机房对"小请求"影响很大**（这个能优化）

扫了 129 个 Cloudflare 候选 IP（同一个域名，只换入口 IP），机房分布：
`AMS 78 个 / LAX 18 个 / SIN 6 个 / DEN 3 个`。同一个域名换个 IP，TTFB 能差 450 ms：

| 入口 IP | 机房 | TTFB 中位 |
|---|---|---|
| 默认解析（`172.67.206.9`） | AMS | 1372 ms |
| `198.41.208.100` | LAX | **923 ms** |
| `198.41.214.100` | LAX | 937 ms |
| `108.162.193.1` | SIN | 1321 ms（但 TCP 连接只要 70 ms） |

原因：Cloudflare 的 Anycast 会按 ISP 的路由把你分到某个机房，而 `cloudflared` 连接器自己也在
某个机房 —— 两者不在同一个时，请求要绕一段骨干网。**换到和连接器同机房的入口，就省掉这一跳。**

**⑤ 结论与建议**

| 用途 | 能不能用 |
|---|---|
| 网页 / 面板 / 后台（几十~几百 KB） | ✅ 可用，首屏 1~1.6 s；换优选 IP 后可到 0.9 s |
| 大文件、相册、NAS 同步、视频 | ❌ 别走隧道，0.45 MB/s。用 frp 直连 VPS 或 Tailscale |
| 手机随时看个状态、开个后台 | ✅ 这就是隧道的正确用法 |

**怎么用上"优选 IP"**（客户端侧改解析，不动 Cloudflare 配置）：

- 原理：Cloudflare 的任意一个 Anycast IP 都能服务你的已代理域名（TLS SNI 匹配即可），
  所以你**不需要**改 DNS 记录，只要让**客户端**把这个域名解析到你测出来最快的那个 IP。
- 做法：电脑改 `/etc/hosts`（`198.41.208.100 dsh.你的域名`）；手机用 AdGuard / 路由器 dnsmasq
  做 host 重写；iOS 用描述文件。改完 `curl -I` 看 `cf-ray` 后缀确认机房变没变。
- 找 IP：用本仓库的 `tools/bench.sh` 或直接
  `for ip in ...; do curl -s -o /dev/null -D - --resolve 你的域名:443:$ip https://你的域名/ | grep cf-ray; done`
- 注意：优选 IP 是**经验值**，会随运营商路由变化；过一段时间要重测。想一劳永逸就用 Cloudflare
  **Argo Smart Routing**（付费，约 $5/月 + 流量费），让 Cloudflare 自己选最优路径。

**自己复现**：

```bash
./tools/bench.sh                                  # 测面板里当前隧道
./tools/bench.sh https://app.example.com          # 测指定域名
head -c 5242880 /dev/urandom > test/site/blob5m.bin   # 给吞吐测试准备大文件
```
- **在「代理规则」页编辑到一半，内容自己变回去了**：v0.7.6 已修。之前每 5 秒拉一次 `/api/state` 会整块重画规则列表，正在输入的字段被服务器旧值覆盖。现在只要动过表单（`input`/`change`）就标脏，轮询只更新顶部警告条，保存成功才重新渲染。
- **一个域名走一条隧道，不是每域名一条隧道**：同一条命名隧道可以在 Cloudflare 里加**多个公共主机名**（`panel.` / `demo.` / …），它们都由同一个 cloudflared 送回本机 Caddy，再由「代理规则」按 `Host` 分流。**不需要为每个域名新建一个出口**；出口只在「要用另一个 Cloudflare 账号 / 另一条独立隧道」时才需要。
- **Tunnel Token 到底复制哪一段**：Cloudflare 的隧道页给的是**整条命令**（`docker run cloudflare/cloudflared:latest tunnel --no-autoupdate run --token eyJh...`）。v0.7.5 起面板两种都吃：整条命令粘进去会自动抠出 `--token` 后面那一串；粘贴框下方还会显示「当前 token 属于隧道 `xxxxxxxx…`」，和你在 Cloudflare 看到的那条隧道对不上就说明拿错了。解析不出来会直接拒绝并提示，不会存进去让你对着一个坏 token 排查半天。
- **出口报「Token 无效 · 已停止自动重试」**：Cloudflare 那边 token 复制不全，或者隧道被删/被轮换过。到 Zero Trust → 网络 → Tunnels → 该隧道 → 复制完整 token（`eyJh...` 一长串），粘贴到「出口设置 → Tunnel Token」保存并启动。v0.7.4 起这种错误会直接停下，不会每 5 秒重试刷日志。
- **出口报「连续 5 次启动失败，已暂停自动重试」**：说明不是偶发抖动，看前面几行 cloudflared 原始输出（域名冲突、协议参数非法、二进制缺失都可能），修好后点「启动」。


### 在面板里直接测速（v0.7.7，不用敲命令）

工具箱页最下面有一张「测速」卡，点一次就把三件事测完：

| 测的东西 | 说明 | 正常范围（本机实测） |
| --- | --- | --- |
| 延迟（10 次小请求） | 浏览器 → 公网 → Cloudflare → 隧道 → Caddy 的往返 | 1.0–1.6 秒（机器在家宽后面就是这个量级） |
| 本机 → Caddy | 面板进程自己打 `127.0.0.1:8080`，不经过隧道 | 3–6 毫秒（这才是"面板本身慢不慢"的答案） |
| 下载 1 / 5 / 20 MB | 同源下载一段流，算 MB/s 与首字节时间 | 0.3–0.5 MB/s（2–4 Mbps，卡在家宽上行） |

测完还会告诉你落在哪个 Cloudflare 机房（读响应头 `cf-ray`，例如 `AMS` 阿姆斯特丹 / `LAX` 洛杉矶 / `SIN` 新加坡）。**同一个域名换优选 IP，只会改延迟，不会改带宽**——带宽的瓶颈是 cloudflared 回源那一段家宽上行。

用法：

1. 打开面板（本机 `http://127.0.0.1:8090` 或公网 `https://panel.你的域名`）
2. 工具箱 → 拖到最下面「测速」→ 选文件大小 → 点「一键测速」
3. 想让数字真实：要测公网就从公网域名打开面板测；要测局域网就从局域网地址打开

背后的两个端点（也可以自己 curl）：`GET /__bench/ping` 返回 `{ok,colo,t}`；`GET /__bench/blob?mb=5` 返回 N MB 零字节流；`POST /api/bench/local {n:5}` 返回本机 → Caddy 的 ttfb 统计。

## 10. 安全清单

- 面板页面自带 CSP（`default-src 'self'`）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: SAMEORIGIN`，脚本只能从同源 `/assets/` 加载。
- `/api/*` 有粗粒度限流：同一来源每分钟超过 1200 次返回 `429`（防误点、也防暴力试口令）。要更细的限流请用 Caddy 的 `rate_limit`（见 `docs/RATELIMIT.md`）。
- 宿主机读不到 `data/state.json` / `access.log`？跑一次 `sudo bash tools/fix-perms.sh`（内部是 `docker exec` 改属主），之后宿主机普通用户也能直接看。
- **面板登录防爆破**（v0.7.3）：同一 IP 10 分钟内输错 8 次密码，锁 10 分钟（返回 429，`Retry-After` 告诉你要等几秒）；期间密码正确的请求仍然放行，不会把自己锁在门外。锁定/失败都写进面板日志。
- `/metrics` 永久免登录（内容只有聚合计数），Prometheus 直接抓；`/badge.svg` 同理。

### 10.1 IP 白名单在隧道后面为什么"不管用"（v0.7.3 已修）

现象：配了「只允许 192.168.1.0/24」，结果公网谁都能进；或者反过来，家里人也进不来。

原因：走 Cloudflare 隧道时，Caddy 看到的 TCP 对端是 **cloudflared / Cloudflare 边缘节点**，不是访客本人。所以你写的 IP 白名单比对的是边缘 IP。

v0.7.3 起面板下发的 Caddy 配置里固定带这两行：

```json
"trusted_proxies": { "source": "static", "ranges": [ "173.245.48.0/20", "…" ] },
"client_ip_headers": [ "CF-Connecting-IP" ]
```

意思是「这些代理段发来的请求，用 `CF-Connecting-IP` 头里的地址当真实客户端 IP」。于是：

- IP 白名单 / 黑名单按**真实访客**判断；
- 访问统计里的 IP 是真实访客，不再是 `127.0.0.1`；
- 面板登录锁定也是按真实访客计数。

段表内置了 Cloudflare 官方 22 段（v4 + v6）。Cloudflare 偶尔会加新段，想手动覆盖就设环境变量：

```yaml
environment:
  - CLOUDFLARE_IPS=173.245.48.0/20,103.21.244.0/22
```

> 自测小技巧：本机 `curl -H 'CF-Connecting-IP: 203.0.113.9'` 不会生效——因为请求来自 `127.0.0.1`，不在可信代理段里，Caddy 会拒绝采信那个头。这正是它安全的地方；要验证就把 `127.0.0.1/32` 临时加进 `CLOUDFLARE_IPS`。

代理出去 = 公网可见。上线前过一遍：

- [ ] 每个对外路径都想过"要不要加基础认证"
- [ ] 管理类界面（路由管理、NAS 后台、数据库面板）**至少**加认证或 IP 白名单
- [ ] 别把面板本身（8090）挂到公网；要挂就加认证 + IP 白名单
- [ ] 导出含 token 的文件不要进 Git（`.gitignore` 已忽略 `data/`）
- [ ] 用命名隧道，别长期用快速隧道（快速隧道没有访问日志、域名随机）
- [ ] 需要严格身份控制 → 上 Cloudflare Access，别只靠基础认证

### 面板自身也上 HTTPS（可选）

面板默认 HTTP（`:8090`），只在局域网里用问题不大。想上 HTTPS（比如手机添加书签、或经隧道给面板自己也开个入口）：

```bash
mkdir -p data/tls
# 用 docker 里的 openssl 生成一张 825 天的自签证书（把 IP 换成本机地址）
docker run --rm -v "$PWD/data/tls:/tls" alpine/openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout /tls/panel.key -out /tls/panel.crt -days 825 -subj "/CN=cf-tunnel-panel" \
  -addext "subjectAltName=IP:192.168.1.55,DNS:localhost"
```

然后在 compose 的 panel 服务里打开两行环境变量（文件里已写好注释）：

```yaml
PANEL_TLS_CERT: /data/tls/panel.crt
PANEL_TLS_KEY: /data/tls/panel.key
```

重启面板，访问 `https://192.168.1.55:8090`（首次会提示证书不受信任，自签证书正常 —— 在自己设备上点"继续"即可）。证书读不到时面板会**自动退回 HTTP** 并在日志里说明，不会起不来。

### 监控：Prometheus + 徽章

- `GET /metrics`：Prometheus 文本格式，含 `cf_tunnel_panel_up`、`cf_tunnel_running`、`cf_tunnel_routes`、`cf_caddy_ok`、`cf_tunnel_up{id,name}`、以及从 access log 汇总的 `cf_tunnel_requests_total{status}`。抓取配置：

```yaml
scrape_configs:
  - job_name: cf-tunnel-panel
    basic_auth: { username: admin, password: 你的面板密码 }   # 没开登录保护就删掉这行
    static_configs: [{ targets: ['192.168.1.55:8090'] }]
```

- `GET /badge.svg`：一张 SVG 状态徽章（`cloudflared 2/2 up`，绿/红自动切），**故意不做鉴权**，可以直接贴在 README 或看板上：

```markdown
![tunnel](https://your-host:8090/badge.svg)
```

每种格式的地址长得完全不一样，填错了不会报错、只会**静默不送达**，所以面板在保存时按格式校验：

| 格式 | 地址长什么样 | 密钥（加签） |
| --- | --- | --- |
| 通用 JSON | 任意 `http(s)://` 地址，收到 `{title,text,event,ts,host}` | 不需要 |
| 钉钉机器人 | `https://oapi.dingtalk.com/robot/send?access_token=…` | 安全设置勾了「加签」才填（`SEC` 开头），签进 URL 的 `timestamp`/`sign` |
| 飞书机器人 | `https://open.feishu.cn/open-apis/bot/v2/hook/…` | 开了「签名校验」才填，签在 body 的 `timestamp`/`sign` |
| Bark（iOS） | `https://api.day.app/你的Key`（自建填自己域名） | 不需要，面板自动拼 `/标题/正文` |

只勾「自定义关键词」的钉钉机器人不需要密钥，但要保证关键词出现在消息里 —— 面板的标题带「掉线」「失败」「换了 IP」，把关键词设成其中任一个即可。

### 10.3 登录会话（比 Basic 更可控）

面板支持两种登录：

| 方式 | 场景 | 能踢掉吗 |
| --- | --- | --- |
| 浏览器会话（cookie `cfp_sid`） | 日常用面板 | ✅ 可以逐个踢 |
| HTTP Basic | curl / 脚本 / Prometheus | ❌ 每次请求现验 |

- 会话 7 天免密、12 小时不动即失效，只存在内存里 —— **重启容器 = 所有会话失效**。
- 「设置 → 登录会话」能看到谁在哪台设备、来源 IP、什么时候登录、最后活动，并能逐个踢掉或「退出全部设备」。
- **同一会话换了来源 IP**（比如 cookie 被复制到别的机器）会在表里打 `换过 IP` 红标，同时写一条审计、推一条通知（可在「通知」里关掉）。
- **改面板口令 / 改只读账号会自动踢掉所有会话**，改完跳登录页重新登。
- 会话鉴权的写请求要求同源（`Sec-Fetch-Site` / `Origin`），跨站请求一律 403，防 CSRF。

### 10.4 界面中英文

右上角 🌐 切换，选择记在 cookie `cfp_lang` 里。服务端渲染导航与 `<html lang>`，前端把页面里 **229 条**文案按「中文原文 → 英文」精确替换；翻不到的新文案会保持中文（不做机翻，避免出现半截英文）。

### 10.5 审计日志

「观测」页底部：谁、什么时候、从哪个 IP、改了什么。只记「改动作 + 失败的请求」，`/metrics`、`/badge.svg`、静态资源、日志流这些高频只读请求不记，避免把日志刷爆。写 `data/audit.log`（JSON Lines，超 2MB 只留最后 3000 行），接口 `GET /api/audit?limit=&q=`。

### 10.6 口令只存哈希（bcrypt）

`state.json` 里的 `panel.pass` / `viewer.pass` 都是 bcrypt 哈希（`$2b$10$…`），不再是明文 —— 备份、导出、
`cat data/state.json` 都不会泄露口令。老版本留下的明文会在启动时自动迁移成哈希（`saveState('migrate-secrets')`），
所以升级后你可能看到多出一个备份文件。

每个 Basic 认证请求都要跑一次 bcrypt（本机 ARM 上 10 轮约 170ms），会把页面加载拖慢一个数量级，因此
**验证成功的 Basic 凭据会在内存里缓存 10 分钟**；改口令时立刻清空。浏览器走的是会话 cookie，不受影响。

### 10.7 容器里跑的是镜像里的代码吗？

`/healthz` 现在直接回答这个问题：

```bash
curl -s localhost:8090/healthz | jq '{version, code, imageCode, drift}'
```

- `code`：磁盘上 `src/` 现算的指纹（SHA1 前 16 位）
- `imageCode`：构建镜像时写进 `/app/.code-hash` 的指纹
- `drift: true`：两者不一致 —— 容器里跑的是 `docker cp` 热替换进去的代码，不是镜像里的。开发时正常，
  生产上危险：下次 `docker compose up -d` 会把你悄悄退回镜像里的版本。

## 14. v0.13.0 更新了什么

0.12 里**故意没做**的两件事，加上一直缺的那类测试。

### 14.1 二次验证（TOTP）

设置 → 二次验证（TOTP）→ **生成二维码** → 用 Google Authenticator / 1Password / Authy 扫 → 输入 6 位数字 → **确认开启**。

- 登录页变成两段：先口令、再 6 位验证码。验证码输入框**只有在口令正确后才出现**，所以光看界面判断不出口令对不对。
- **10 个恢复码只显示一次**，每个登录一次即失效。手机和恢复码都丢了，只能去主机上改 `data/state.json`。
- 允许 ±1 个步长（±30 秒）的时钟偏差，手机时间稍快也能用。
- 密钥不会从服务端漏出：`/api/state` 里只有 `{enabled, recoveryLeft}`，扫码那一份只在你刚生成时可见。
- **Basic 认证仍然跳过 TOTP**，这是故意的：它是机器凭证（curl、Prometheus、脚本）。要全链路都有二次验证，就别用 Basic，走浏览器登录换会话。
- 关闭二次验证必须给一个当前验证码或恢复码，所以「偷到 cookie 顺手关掉第二因素」这条路走不通。

### 14.2 角色：admin / operator / viewer

设置 → 运维账号。三个角色，走白名单：

| | admin | operator | viewer |
| --- | --- | --- | --- |
| 看所有页面与状态 | ✅ | ✅ | ✅ |
| 改隧道 / 规则 / 分享 / 维护模式 | ✅ | ✅ | — |
| 公共主机名增删 | ✅ | ✅ | — |
| 通知、Cloudflare 凭证、面板口令 | ✅ | — | — |
| 导入 / 回滚整份配置 | ✅ | — | — |
| 踢别人的会话、二次验证设置 | ✅ | — | — |

`operator` 是**写接口白名单**（`src/core/perm.js`）：新加的接口默认对它关闭，被拒时返回的是「面板口令只有管理员能改」这类原因，而不是一句干巴巴的 forbidden。

### 14.3 CI 里跑真 Caddy

新增 `test/e2e-caddy.mjs` 与 CI 的 `e2e` 作业：用 `caddy:2.11.9-alpine` 起真 Caddy（admin 在 `:20190`），面板对着它跑，推一条探针规则，经 Caddy 取回响应，并断言未命中路径仍是 404。**这是唯一能抓住「生成的 Caddy JSON 字段名写错」的测试**（`load_balancing.selection` 和 `selection_policy` 那次就耗了一下午）。

脚本会先把规则表快照到 `/tmp`，无论成败都从快照还原 —— 上一版是从「当前 state」还原，结果一次中途崩溃把线上规则全删了。

## 16. 滚动升级（两个实例同时活，零中断）

以前重启面板就是几秒钟 502（Caddy 没有可用上游）。现在可以两个实例同时活着，切换过程一个请求都不丢。

**机制**

- 实例在 `data/` 里抢一个**租约**文件（5 秒心跳、15 秒过期）。持有者是 **leader**，只有它能写
  `state.json`、下发 Caddy 配置、拉起 `cloudflared`。
- 其它实例以 **standby** 启动：页面和查询接口照常能用，任何写操作返回
  `409 {"code":"STANDBY"}`，并告诉你是谁在当 leader。
- leader 退出时立刻删租约，standby 约 5 秒内自动接管。
- 面板自己那条规则下发成**双上游**（`:8090` + 预留槽位 `:8095`），`selection_policy: round_robin`
  + `try_duration 3s` + `/healthz` **主动健康检查**（2 秒一次、1 秒超时、连挂 2 次才剔除）。
  一台挂掉时，同一个请求内就会重试另一台，随后把死的那台移出轮转。
- 备份实例还会为每条**命名隧道**常驻一个 **cloudflared 热备连接器**，交接过程中隧道不会
  瞬间失去最后一个连接。（快速隧道故意跳过：它的域名是每个进程各自分配的，两个连接器只会互相打架。）
- 线上实测（每 250ms 探测一次 `https://…/healthz` 横跨切换）：加暖连接器前 **7 次 530 ≈ 6 秒**
  不可用；加上之后 **1 次 530 ≈ 0.25 秒**。

**一次性开启**

```yaml
environment:
  PANEL_SLOT_PEERS: "8095"   # 长期预留第二个槽位
```

重建（或 recreate）一次面板容器让环境变量生效。这个端口要一直空着（只在升级过程中被占用）。

**升级**

```bash
tools/rolling-upgrade.sh                  # 干跑：preflight + 打印计划，不动任何东西
tools/rolling-upgrade.sh --apply          # 真做
tools/rolling-upgrade.sh --apply --prune  # 顺手删掉停下来的那一色

# 全新部署（还没有任何实例在跑）——创建蓝色槽位
tools/rolling-upgrade.sh --bootstrap --apply
```

容器名是**固定的一对**，因此永远不会和 compose 抢名字：

| 槽位 | 容器名 | 端口 |
| --- | --- | --- |
| blue | `cf-tunnel-panel-blue` | 8090 |
| green | `cf-tunnel-panel-green` | 8095 |

每次执行它会自己判断当前是哪个颜色，然后在**另一色**上起新实例 —— 全程不改名，
跑多少遍两个名字都稳定，compose 也插不进来。（`docker-compose.yml` 里的 panel 服务放在
`profiles: ["bootstrap"]` 下，裸跑 `docker compose up -d` 只会管 Caddy 和演示服务。）

脚本流程：起另一色 → 等它 `standby` → 停掉当前色 → 等它 `leader` → 验证 → 可选 `--prune`
删掉停下来的那一色。接管失败会自动把老实例拉回来并以非 0 退出。

**坑**

- 记得 `docker inspect` 看 leader 有没有 `PANEL_SLOT_PEERS`：没有的话它只知道自己的端口，
  Caddy 只有单上游，脚本会退化成「先停后起」（1~3 秒 5xx）。
- **别让测试实例指向生产 `CADDY_ADMIN`**。一个 `data/` 是空的实例会老老实实把它那份默认
  （只有一条规则）的配置推上去，把你的规则冲掉。所以现在「启动时 state.json 不存在」会拒绝
  首次下发（除非 `PANEL_ALLOW_FRESH_PUSH=1`）；`CADDY_ADMIN` 也不再自动回退到 2019/20190
  （确实需要旧行为就设 `PANEL_ADMIN_FALLBACK=1`）。
- 租约刻意只用时间戳：容器共享 PID 命名空间，`kill(pid, 0)` 永远成功，按 pid 判断没有意义。
